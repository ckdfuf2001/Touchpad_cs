1. 개요

TouchMousePointer는 Windows 8.1/10/11 태블릿·컨버터블용 가상 트랙패드(온스크린 마우스)다. 터치스크린을 트랙패드로 바꿔 표준 커서를 조작하므로, 손가락이 타깃을 가리지 않고 롤오버 메뉴·툴팁·창 리사이즈·작은 버튼 조작이 가능해진다. 본 문서는 C:\Program Files\TouchMousePointer 실측 분석과, 그 동작·파일호환 클론 구현 기록이다. 현행 클론은 v2 (C#/WPF, cs/TouchPadCloneV2/)이며, 초기 프로토타입 v1 (Python/tkinter, touchpad_clone/)은 입력 방식의 구조적 한계로 v2에 자리를 넘겼다 (경위 §9).

2.2 원본 아키텍처

핵심 원리 3줄 요약. ① 마우스 드라이버를 쓰지 않고 화면 전체(또는 플로팅 영역)에 투명 최상위 윈도우를 설치한다. ② 터치 이동 델타 × 속도/가속도 = 커서 상대이동으로 변환한다. ③ 풀스크린에서는 실제 커서를 투명 커서로 숨기고 소나·궤적·가짜 화살표를 오버레이로 그린다.

2.3 원본 모드 전환 (중요 — 상단 스와이프 영역은 없음)

공식 도움말·스크린샷 전수 확인 결과, 원본에는 화면 상단 전용 스와이프 영역이 존재하지 않는다. 모드 전환 수단은 ① 패드 위 핀치 아웃=풀스크린 / 핀치 인=창모드 복귀(꽤 멀리 벌려야 함), ② 트레이 아이콘 탭(램프 점등=풀스크린 ON), ③ 제스처에 할당하는 Layout… 전환과 패드의 menu 타일이다. 클론의 상단 ModeStrip(§6.2)은 요청받은 편의기능으로 원본에는 없는 확장이다.

3. 타일 레이아웃 엔진 (원본 INI 문법)

3.1 문법

[floatpad]                       ; 섹션 = 레이아웃 1종 (floatpad/leftpad/…/ArtistPad/…)
scale=100,100                    ; 기준 스케일 (무시 가능)
aspect=1,1                       ; 가로세로비 힌트 (일부 섹션)
tile000=padframe,0,20,100,80     ; tileNNN=종류,x,y,너비,높이[,extra…]
tile001=lbtn,0,0,50,20
tile004=pad,0,0,100,100          ; 입력층은 보통 마지막(최상위 z-order)
좌표는 패드 창 기준 0~100 상대 %. 렌더는 섹션 순서대로, 히트테스트는 역순(나중 타일 우선) — 원본 z-order와 동일. tile002=VK_CONTROL,0,0,25,20처럼 가상키, tile010=C,0,5,50,15,7,Copy처럼 한 글자 키도 된다.

7. vJoy 설치 안내

원본의 VJoy64.dll은 Shaul Efraim의 오픈소스 vJoy 가상 조이스틱 SDK다. Preset WASD gaming.ini(풀스크린 31타일)가 게임에 조이스틱 축·버튼 신호를 보내기 위해 사용한다. vJoy는 서명된 드라이버라서 동봉이 불가능하고 반드시 별도 설치해야 한다 (원본 설치 도움말이 가리키는 곳과 동일한 공식 링크):

9. 왜 v2인가 — v1의 구조적 한계와 깃 리서치

v1의 발진 사고. v1(tkinter)은 OS 커서 좌표에서 이동 델타를 쟀다. 그런데 그 좌표 안에는 직전에 v1이 쏜 이동량이 포함되어 있었다: 측정값 = 손가락 + 자기이동. 이득>1에서 양의 피드백이 되어 실측 로그에 d=(-1137,-711) -> (-11880,-6606)이 8회 반복 — 커서가 화면 모서리↔모서리로 핑퐁쳤다. 보정·퓨즈로 완화는 됐지만, 에뮬 마우스 기반 설계 자체가 흔들리는 토대였다.
깃 리서치. arand4/TKM(Touch Keyboard & Mouse, WPF/.NET 8)의 Trackpad.xaml.cs를 직접 확인: WPF 진짜 터치 이벤트 (TouchDown/Move/Up + TouchDevice.Id별 추적 + CaptureTouch)를 쓰고, 마우스 핸들러에 if (e.StylusDevice != null) return;으로 터치 승격 이벤트를 차단한다. 델타는 컨트롤 좌표계 손가락 위치에서만 재서 OS 커서와 무관 — 발진이 구조적으로 불가. v2는 이 패턴을 따른 자체 구현이다. 주의: TKM README엔 MIT라 돼 있으나 LICENSE 파일은 GPL-3.0이라 코드를 베끼지 않았다. SHU-Anonymous/virtualTouchpad(MIT, C#)도 찾았으나 구시대 방식이라 미채택. 윈도우 내장 가상 터치패드(작업표시줄 → 터치패드 단추)도 설치 없는 대안으로 유효.
